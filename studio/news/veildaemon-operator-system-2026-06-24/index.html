VeilDaemon Becomes an Operator System

June 20–24, 2026 · VeilDaemon · Operator · Handler

← Development record

On June 19, VeilDaemon was an intake page with good atmosphere. By June 24 it was an Operator system with a Handler on the other end.

June 20: reports

Needlepoint report intake and admin APIs went in, routed through a dedicated API subdomain. The recovered-operator-reports index opened the same day.

June 21: the Operator console

  • Debrief intake with redaction. Sensitive details are flagged, and the Operator approves the public version before anything is sent.
  • A local Operator console aligned to the core field sheet, including trackers, a creation budget, and skill rank previews.
  • The Lotus workspace, with active Misfire and Lotus expression.
  • Intake gating. The Operator file opens after intake, not before.

June 22–23: provenance

Public provenance and archive metadata were added. Discord routes moved behind a server redirect. Scannable barcodes went onto the stream overlays and reward cards.

June 24: the Handler

  • Operator files can be imported, carry equipment, and enforce carry limits.
  • The Handler Dashboard landed, with its console modules and Handler authorization unlock packets.

Saves stayed local the whole time. Nothing leaves the device unless the Operator sends it.

From here, the Handler runtime took shape.
