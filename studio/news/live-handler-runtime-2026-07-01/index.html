The Live Handler Runtime Takes Shape

June 26 – July 1, 2026 · Handler · Operator

← Development record

The Handler Dashboard landed on June 24. Over the next six days it turned into the runtime tables use now.

June 26–28: the table

  • Table triggers and an entity library, with Needlepoint templates whose Entity and Zone loops are locked so a case cannot be half-loaded.
  • Operator trackers on the Handler side.
  • Collapse staging per break type, with Rewrite scaffolds. Scene consequences and attention consequences were split, because they are not the same thing.
  • A PREP / LIVE / ARCHIVE split, so pressure controls only appear when the table is live.

June 30: anchors and clues

  • Anchor states, including Idle, which applies pressure when confirmed, and per-Needlepoint overrides.
  • Clue Integrity, tracked in the live runtime and wired into the pressure system.
  • Soften Case Pressure that actually applies visible relief.

July 1: pressure and Load

  • Unified Handler pressure controls, with pending alerts and a manual preview. Pressure is previewed before it lands.
  • An Operator track prompt queue for Stability and Harm, plus trigger undo.
  • A Presentation Pressure registry wired into both apps, then a universal Load architecture across the presentations. Sanguine traded its hunger track for blood load, and Wraith moved to an essence-load model. On July 2, seven more presentation types arrived, each with its own drift.

By July 1, the runtime at the table was substantially the one in use now.

Some systems tell you when the table is losing. This one tells you what is beginning to notice.
